# ISS-002: MDFC errors in management workflow for new subscriptions

- **Date:**     2026-07-07
- **Severity:** Medium
- **Stack:**    Management (`main.mdfc.tf`)
- **Status:**   Resolved

---

## Description

Failure to configure MDFC settings for newly added subscriptions when placed under the `core` management group.
Terraform error in `plz-management` workflow when attempting manual run after a new subscription has been added.

```shell
Error: Failed to retrieve resource
│   with azapi_resource.mdfc_workspace["{SUBSCRIPTION_ID}"],
│   on main.mdfc.tf line 37, in resource "azapi_resource" "mdfc_workspace":
│   37: resource "azapi_resource" "mdfc_workspace" {
│ 
│ checking for presence of existing Resource: (ResourceId
│ "/subscriptions/{SUBSCRIPTION_ID}/providers/Microsoft.Security/workspaceSettings/default"
│ / Api Version "2017-08-01-preview"): GET
│ https://management.azure.com/subscriptions/{SUBSCRIPTION_ID}/providers/Microsoft.Security/workspaceSettings/default
│ --------------------------------------------------------------------------------
│ RESPONSE 401: 401 Unauthorized
│ ERROR CODE: Subscription Not Registered
│ --------------------------------------------------------------------------------
│ {
│   "error": {
│     "code": "Subscription Not Registered",
│     "message": "Please register to Microsoft.Security in order to view your security status"
│   }
│ }
```

---

## Impact

Deployment pipeline for `plz-management` stack fails when a new unregistered subscription is added.

---

## Resolution

The subscription does not have the `Microsoft.Security` resource provider registered. 
Azure requires resource providers to be registered before you can create or read resources of that type.

1. Register the resource provider `Microsoft.Security` for the subscription.

```shell
az provider register --namespace Microsoft.Security --subscription {SUBSCRIPTION_ID} --wait
```

2. Verify the process completed successfully.

```shell
az provider show --namespace Microsoft.Security --subscription {SUBSCRIPTION_ID} --query "registrationState"
```

3. Re-run the workflow.
